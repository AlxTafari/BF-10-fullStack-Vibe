# Что можно добавить боту

Отсортировано по трудозатратам. Ничего из списка не ломает текущую архитектуру —
всё ложится в существующие слои.

**Уже сделано:** меню команд (`/set-commands`), `/source`, `/rates`, флаги валют,
сумма в запросе (`100 EUR в USD`), словарь синонимов и русских названий
(«евро», «долларов», «в юанях»), отдельное сообщение когда валюты нет у провайдера.

---

## Почти бесплатно (1 файл / 1 запрос к API)

### 1. Меню команд рядом с инпутом (`setMyCommands`)

То самое меню слева от поля ввода. Один разовый запрос к Bot API, как `setWebhook`.

- **Что:** `POST /setMyCommands` со списком `{command, description}`.
- **Где:** новый `scripts/setCommands.ts` + строчка в `package.json`.
- **Пример:**
  ```
  start   — как пользоваться
  help    — справка и примеры
  rates   — курсы популярных валют к USD
  source  — текущий источник курсов
  ```
- **Плюс:** отдельно можно задать кнопку меню — `setChatMenuButton` (по умолчанию
  уже показывает список команд).

### 2. `/source` — показать текущий провайдер и время обновления

- **Что:** ответить именем провайдера + `asOf` из снимка курсов.
- **Где:** ветка в `handleIncomingMessage`, данные уже есть в `RateSnapshot`.
- **Труд:** ~10 строк, новый use case не нужен.

### 3. Чистить `@botname` в командах (работа в группах)

В группах Telegram шлёт `/rates@bf_currency_bot`. Сейчас распознавание команд это
не учитывает.

- **Где:** `handleIncomingMessage`, регулярка команд — срезать `@\w+`.
- **Труд:** правка одной строки + тест.

### 4. Сообщать, когда кодов больше двух

Сейчас при `EUR GBP JPY` молча берём первые два. Лучше сказать пользователю, что
считаем `EUR → GBP`, остальное игнор.

- **Где:** `handleIncomingMessage`, `replyText`.

### 5. Флаги валют в ответе

`🇪🇺 EUR / 🇺🇸 USD`. Статическая мапа `код → эмодзи`, без API.

- **Где:** `replyText` + мапа в `domain`.

## Небольшая доработка (новый use case или парсер)

### 6. Сумма в запросе: `100 EUR` → сколько это USD

- **Что:** парсер вытаскивает число перед кодом; use case умножает.
- **Где:** `application/parsing` — добавить `extractAmount`; `getRateAgainstUsd`
  принимает опциональный `amount`.
- **Труд:** парсер + ветка форматирования. Тесты на `"100 eur"`, `"1 000,50 USD"`.

### 7. `/rates` — корзина популярных валют

- **Что:** один снимок курсов, вывести 6–8 валют к USD списком.
- **Где:** новый `getPopularRates` use case (список кодов — константа), формат в `replyText`.
- **Труд:** ~30 строк. Снимок и так кешируется, лишних запросов нет.

### 8. Историческая справка: `/history EUR 2024-01-01`

- **Что:** Frankfurter умеет `GET /v1/{date}`. Для OXR историч. данные платные —
  фича доступна только на провайдере `frankfurter` (или добавить в порт метод
  `getSnapshotAt(date)` с graceful "не поддерживается").
- **Труд:** метод в порте + реализация у Frankfurter + use case.

### 9. Подсказка при опечатке в коде

`ERU` → «может, EUR?». Расстояние Левенштейна до известных кодов.

- **Где:** ловим `UnknownCurrencyError`, ищем ближайший код из `KNOWN_CURRENCY_CODES`.
- **Труд:** маленькая функция расстояния + ветка в обработчике ошибки.

### 10. Изменение за сутки (дельта)

`EUR: 0.92 (+0.4% за день)`. Два снимка — сегодня и вчера (Frankfurter `/v1/{date}`).

- **Труд:** зависит от #8; арифметика простая.

## Заметная фича (стоит закладывать время)

### 11. Inline-режим: `@bf_currency_bot EUR` в любом чате

- **Что:** `answerInlineQuery` — бот отвечает прямо в поле ввода любого диалога,
  без добавления в чат.
- **Где:** новый адаптер-ветка (`inline_query` в Update), новый маппер; use cases
  переиспользуются как есть.
- **Труд:** средний — новый тип апдейта, включение inline mode у @BotFather,
  формат `InlineQueryResultArticle`.

### 12. Переключение провайдера на лету: `/provider frankfurter`

- **Проблема:** нужно где-то хранить выбор на чат. На serverless память между
  запросами не живёт → нужен внешний стор (Upstash Redis / Vercel KV — бесплатные
  тарифы есть).
- **Компромисс без стора:** разовый флаг в сообщении — `EUR !frankfurter` —
  парсер вытаскивает провайдер для конкретного запроса. Состояние не нужно.
- **Где:** `parsing` + фабрика провайдеров получает override.

## Инфраструктура / качество (не фичи, но по делу для сдачи)

### 13. GitHub Actions — прогон тестов на push

- `.github/workflows/ci.yml`: `npm ci && npm run typecheck && npm test`.
- **Труд:** один файл. Для «публичного репозитория» в задании — плюс к оценке.

### 14. Заглушка на `GET /`

Сейчас корень отдаёт 500. Добавить роут `GET /` → `{ ok: true, bot: "currency-converter" }`
или редирект на репозиторий.

### 15. Vercel Cron для прогрева

`vercel.json` → cron раз в 10 мин дёргает `/health`, чтобы холодный старт не ловил
первый ответ пользователя. Нужно только если заметны задержки.

---

## Что НЕ стоит делать (переусложнение под этот объём)

- Полноценная БД / история запросов пользователей.
- Мультиязычность (i18n).
- Rate limiting на пользователя.
- Свой слой кеша поверх Redis (хватает in-memory на время жизни инстанса).
- Graceful shutdown / очереди — работа слишком лёгкая.
