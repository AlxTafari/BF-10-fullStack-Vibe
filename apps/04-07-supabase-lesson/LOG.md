## 2026-11-17 — S10: чистовик спеки, состав индекса RAG
**Цель:** пройти открытые вопросы §4 спеки S10 по одному, решить, что индексируется.
**Решения:**
- §4.1 эмбеддинги: Gemini, размерность 768. gte-small перепроверен на наборе Лавраки (6 документов + 10 блюд, 10 вопросов, критерий — топ-3 для 9/10): gte-small 6/10, оценки всех фрагментов в коридоре 0.85–0.91, порог «не знаю» не поставить; `gemini-embedding-001` (768) 10/10, разброс 0.13–0.28. Подробности — QA.md.
- §2.А источники индекса: документы ресторана и блюда. FAQ и поля `restaurants` не индексируются (остаются `listFaq` / `getRestaurantInfo`).
- Стоп-лист: блюдо в стоп-листе поиск не прячет. Информацию о блюде гость получает всегда, стоп — флаг в результате; модель говорит, что сейчас позиция закончилась и уточнить можно в ресторане. Применяется везде одинаково: `searchKnowledge`, `searchMenu`, `getDishDetails`, `filterMenuByAllergens` отдают блюдо с флагом `is_available` (меняется правило S09 «стоп-лист для AI = отсутствующее блюдо»; правка tools, промпта, тестов). Неопубликованные блюда по-прежнему скрыты.
- §4.2 документы: редактор в админке, без загрузки файлов.
- §4.3 подборки: ссылки на блюда по `menu_items.id` (таблица связей, выбор блюд в редакторе); найденная подборка отдаёт блюда с текущим флагом стоп-листа.
- §4.4 поиск: только векторный (косинус), без полнотекстового.
- §4.5 переиндексация: синхронно, админка после сохранения вызывает Edge Function. Правка мимо админки (SQL, seed, будущий My-Rest) оставляет старый вектор — принятое ограничение.
- §4.6 нарезка документов: по структуре — заголовки `##`, иначе абзацы; мелкие склеиваются до ~500–800 токенов, короткий документ целиком, без перекрытия, в каждый фрагмент добавляется название документа. Блюдо — один фрагмент.
- Мок-база для проверки и будущего seed — `supabase/scripts/rag-eval/` (59 документов, 32 блюда, 41 вопрос, `pnpm eval:rag`). Ресторан вымышленный, тон мультяшный, рыжий кот Порто — талисман, в меню позиции «для кота». Тон шутливый, факты однозначные. Прогон: топ-3 35/35, топ-1 31/35; чистого порога «не знаю» нет (пересечение 0.001).
- Порог «не знаю»: низкий порог (≈ 0.60, константа, пересматривается по `eval:rag`) отсекает явный мусор; прошедшие фрагменты читает модель и сама решает, есть ли в них ответ (правило «не выдумывать»).
- Модель: `gemini-embedding-001`.
- Векторы для данных мимо админки: и скрипт для разработки (после `db reset`), и кнопка «Переиндексировать всё» в админке — одна Edge Function внутри. CI на фейковых эмбеддингах.
- Спека S10 переписана из черновика: решения в §4, сессии 1 данные → 2 индексация → 3 поиск и агент → 4 админка, приёмка §5.
**Осталось:**
- Сессия 1 спеки S10.
- Проверить нарезку на длинном документе (в мок-базе все короче лимита) — сессия 2.

## 2026-11-17 — S10, сессия 1: схема базы знаний и seed
**Цель:** миграция (pgvector, документы, связи подборок, чанки, поля индексации, триггеры, RLS), seed из мок-базы скриптом, RLS-тесты, типы админки.
**Решения:**
- Связи с блюдами — только у подборок (`collection`). У «Вино к рыбе», «Вино к мясу», «Ципуро и узо», «Без алкоголя», «Как угостить кота» связи из мок-базы убраны, текст не меняется. Минус принят: стоп-лист вина из такого документа агент узнаёт через `searchMenu`.
- Типы в `documents.json` переведены на коды БД («кот» → `other`). Тексты подборок без перечней блюд, «Бронь и опоздания»: к менеджеру — больше 20 человек.
- Seed разделён: `seed.sql` — ресторан и FAQ (руками), `seed-knowledge.sql` — меню и база знаний, генерируется `pnpm seed:gen` из `rag-eval/*.json` (порядок — `[db.seed] sql_paths`). Постоянные uuid по позиции (`…b0NN` категории, `…c0NN` блюда, `…d0NN` документы). КБЖУ и порции первых блюд перенесены в `dishes.json`.
- Связи и чанки получили составные FK `(источник, restaurant_id)`: «тот же ресторан» гарантирует БД, а не только RLS. Поэтому у `knowledge_document_dishes` есть `restaurant_id` (сверх спеки).
- Служебные поля индексации от клиента (`anon`/`authenticated`) триггер молча откатывает, а не падает: форма может прислать строку со старым статусом.
- RPC начала/завершения индексации и `match_knowledge` (и их RLS-кейсы) — в сессиях 2 и 3, вместе с кодом, который их вызывает.
- Проверка без локального Docker: ветка + PR #6, job integration поднимает Supabase в раннере с миграциями и обоими seed-файлами. Зелёный: админка 376 тестов (RLS 62, из них 11 новых), бот 287 / 0 failed — сценарии на 32 блюдах не сломались.
- PR #6 смержен, CI выкатил миграцию в dev; seed залит (`db:seed:remote`): 10 категорий, 32 блюда, 59 документов, 43 связи, чанков 0 — ждут индексации. Типы админки перегенерированы по dev.
**Осталось:**
- Сессия 2: индексация.
- `pnpm eval:rag` после правки текстов подборок — в сессии 2.
- Подборка «С детьми» содержит «Рыбку для кота»: проверить в `eval:ai` (сессия 3), что агент не предлагает её как еду.
