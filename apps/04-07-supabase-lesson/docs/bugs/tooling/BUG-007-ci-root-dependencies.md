# BUG-007 — CI пропускает изменения общих зависимостей приложения

- **Статус:** open
- **Важность:** medium
- **Область:** tooling
- **Модуль:** .github/workflows/guest-bot.yml:20–30
- **Найден:** 2026-11-17, code review
- **Спринт-источник:** ревью текущего приложения, не относится к спринту

## Симптом, воспроизведение и причина

Оба фильтра `paths` учитывают только каталог приложения и сам workflow. При этом установка использует корневые `pnpm-lock.yaml`, `pnpm-workspace.yaml` и `package.json`. Изменение только lock-файла, например версии транзитивной зависимости админки, не запустит проверки и публикацию этого приложения.

**Воспроизведение:** PR с изменением только относящихся к админке записей корневого lock-файла. Ожидается запуск Guest bot; ни один заданный путь не совпадёт. Состояние branch protection не проверялось; последствия для возможности merge зависят от него.

**Доказательство:** статическая проверка списка путей и команд установки. Семантика фильтра подтверждается [документацией GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushpull_requestpull_request_targetpathspaths-ignore). Тестовый push/PR не создавался.

**Предложение:** добавить в оба списка `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `package.json`; при появлении общей конфигурации также включать её. Более сложный анализ графа зависимостей для этого проекта пока не нужен.

**Регрессия:** изменение каждого общего файла запускает workflow; изменение изолированного другого приложения без общих файлов не запускает.
