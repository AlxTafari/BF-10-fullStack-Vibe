# Гостевой бот ресторана (04-05-supabase-lesson)

Стек: как в `../03-supabase-lesson` (Supabase Edge Functions на Deno, Telegram, TypeScript, слои domain / repositories / telegram / handlers). Админка: Vite + React + TS, shadcn/ui, TanStack Router (не Next.js), Redux Toolkit + RTK Query, Supabase Realtime (WebSocket), курсорная пагинация чата. CI/CD — предпоследний шаг роадмапа (S08).


## Архитектура (обязательно)

Чистая архитектура, правило зависимостей — **ADR-008**. Зависимости только внутрь: обработчики → `services` → `repositories` / `domain`. Обработчик не ходит в репозиторий и не содержит бизнес-логики; `domain` не знает про Supabase и Telegram; в админке компоненты не обращаются к Supabase напрямую, только через RTK Query. Перед коммитом кода бота — `pnpm check:layers`. Без DI-контейнеров и интерфейсов «про запас».

## Документация реализации (`docs/`)

**Читать до написания кода.**

- `docs/STATE.md` — **читать первым.** Где стоим: что сдано, что построено, чем код сознательно
  отличается от ADR, какие хвосты открыты. Короткий, обновляется в конце спринта.
- `docs/architecture/decisions.md` — ADR. **Закон.** Расхождение кода с ADR — либо баг, либо повод
  явно изменить ADR. **Исключение:** статус «Отложено» — зафиксированное упрощение, его отсутствие
  в коде не баг. Сводка расхождений — `docs/STATE.md` §3.
- `docs/architecture/domain-model.md` — сущности, поля, индексы, инварианты.
- `docs/roadmap/README.md` — действующий план. `docs/roadmap/sprints/` — спеки спринтов: один срез =
  схема + сервер + экран. Файл спринта — спека «что делать», по факту не переписывается; факт живёт
  в `docs/STATE.md`.
- `docs/archive/` — архив: журнал завершённых спринтов. Открывать точечно, за причиной конкретного решения.

## Файлы сессии

**В корневых `LOG.md` и `QA.md` живёт только текущий незакрытый спринт.** Читать в начале сессии —
их, а не архив.

Начало сессии: `docs/STATE.md` → спека текущего спринта → корневые `LOG.md` / `QA.md`.
Конец сессии: коммит, запись в `LOG.md`, диалоги в `QA.md`. `STATE.md` и ADR — **только** при
закрытии спринта.

### Ритуал закрытия спринта

**Спринт не закрывается без явного «да» пользователя на приёмке.** Прогон, ревью, зелёные
`typecheck`/`lint`/`build`/тесты — не повод закрыть.

После «да»:

1. Архив — файлы с именем спринта, как у спеки (`S01-data-and-webhook`): `LOG.md` → `docs/archive/log/S01-data-and-webhook.md`, `QA.md` → `docs/archive/qa/S01-data-and-webhook.md`. Содержимое переносится дословно.
2. Строка-указатель в `docs/archive/README.md`.
3. `docs/STATE.md` — сданный спринт (§1), что построено (§2), новые расхождения с ADR (§3), хвосты (§4).
4. ADR, затронутые спринтом, — сменить статус.
5. Корневые `LOG.md` / `QA.md` — после переноса в архив сбросить к пустому шаблону (заголовок + формат записи). Копии в корне не остаются: содержимое живёт только в архиве.

## Баг-репорты

Находка **вне рамок текущей сессии** (другой спринт, другой слой, сессия по роли код не правит —
прогон, ревью, диагностика) не чинится на месте: репорт в `docs/bugs/frontend,backend,tooling/` по
`docs/bugs/TEMPLATE.md`, строка в таблицу `docs/bugs/README.md`. Нумерация `BUG-NNN` сквозная.
Находка в рамках сессии чинится сразу, репорт не нужен.

Причина в репорте помечается честно: «подтверждена» (лог, стектрейс, DOM, запрос к БД) или «гипотеза».
