## 2026-10-13 — Спеки S04–S06 (админка)
**Цель:** написать подробные спеки трёх спринтов админки.
**Решения:**
- Обсуждали схлопывание S04–S06 в один спринт (общий каркас, одна Realtime-подписка). Решено оставить **три спринта** — у каждого свой главный риск и своя ручная приёмка: S04 — Auth + первые RLS-политики, S05 — Realtime + безопасная смена статусов, S06 — курсорная пагинация чата. Нумерация роадмапа не менялась.
- Принцип RLS: каждая спека добавляет только те политики, что нужны ей (S04 — справочники и `restaurant_managers`, S05 — чтение заявок, S06 — чтение диалогов). Запись статусов заявок — только через RPC `set_booking_status` / `set_guest_request_status` (матрица переходов, оптимистичная блокировка `p_from`, атомарное подтверждение изменения брони); прямого `update` у клиента нет.
- S05 закрывает хвост STATE §4: подтверждение изменения брони переводит исходную в `cancelled` в одной транзакции.
- S06: курсор строкой из БД (без `Date`, иначе теряются микросекунды), выборка через RPC (а не `.or()` с `+` в URL), правило `pageSize + 1`, сообщения вставляются в кэш по порядку, а не «в голову»; `messages.kind` вместо префикса `[кнопка]`; триггер ведёт `last_message_*`, бот перестаёт вызывать `touchConversation`.
- Подписка Realtime: S05 — на уровне защищённого layout (нужны бейджи), S06 — на уровне раздела «Чаты» (диалоги + сообщения открытого диалога).
**Осталось:** ответить на открытые вопросы §4 каждой спеки перед стартом соответствующего спринта (блокирующие помечены в спеках); обновить `roadmap/README.md` (ссылки добавлены).
