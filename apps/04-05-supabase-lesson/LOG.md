## 2026-11-11 — S09 сессия 2: агент и вопросы по меню
**Цель:** слой `llm/` (Gemini), агент `runAgentTurn` с tools на сервисах ядра, `filterMenuByAllergens`, маршрут свободного текста агенту при `ai_enabled`, приветствие AI-помощника, деградация, суточный лимит, `messages.meta`.
**Решения:**
- Сессия 1 смержена (PR #3): `integration` на PR прогнал миграцию и RLS-тесты, deploy применил миграцию к удалённой БД без ошибок. Проверка миграции из «Осталось» сессии 1 закрыта.
- Работаем прямо в `main`, коммиты локально по этапам; push только по команде: push в `main` сразу выкатывает бота.
- Метод SDK — `generateContent` (ничего не хранит у Google, окно истории передаём сами), не Interactions API. SDK `npm:@google/genai@2.31.0`.
- Thought signatures Gemini 3 возвращаются внутри хода через непрозрачное `providerState` ответа LLM: типы Google не выходят из `llm/`. Между ходами не нужны — история идёт текстом.
- Webhook остаётся синхронным: повторная доставка при таймауте отсекается `registerUpdate`. Проверить на живом боте.
- Окно истории — сообщения `kind` `text`/`search`, без `[кнопка] …`.
- Модель: рекомендована `gemini-3.6-flash` (стабильная, бесплатный уровень, function calling); задаётся секретом `GEMINI_MODEL`.
- SDK без повторов внутри (`retryOptions.attempts = 1`): по умолчанию до 5 попыток с паузой до 60 с, это больше бюджета хода.
- Стоп-лист для AI: tools не отдают модели блюда с `is_available = false` (списки, подбор по аллергенам, карточка — `not_found`). Кнопочное меню их по-прежнему показывает с пометкой «недоступно». Приёмка §5 п.4.
- Клиент Gemini создаёт `services/ai/llm.ts`, не `index.ts`: обработчики не импортируют `llm/` (тесты и `testing/` — исключение, им нужен фейк).
- Нет `GEMINI_API_KEY`/`GEMINI_MODEL` → бот как до S09 (поиск блюда, старое приветствие), а не запасной ответ на каждый текст.
- Сбой чтения `restaurant_ai_settings` → AI считается выключенным: рубильник менеджера важнее.
- Кнопка «Карточка блюда» под ответом агента подписана названием блюда: при двух блюдах одинаковые подписи неразличимы.
- «Можно голосовым» в приветствии появится с голосом (сессия 4).
- Тесты агента — интеграционные (фейковый LLM + БД с seed), гоняются только в CI: локально нет Docker.
- В seed нет опубликованного блюда с `allergens = null` — для приёмки §5 п.3 (группа «состав не указан») нужно поправить seed или блюдо в админке.
- Первый прогон на живом боте: после 1–3 ответов — `aiFallback: "quota"` (429, бесплатный уровень, подтверждено по `messages.meta`). Один вопрос гостя = 2–6 вызовов модели (раунды tools), первый ответ — 17 с. Проект переведён на платный тариф, модель прежняя (`gemini-3.6-flash`).
- Безопасные оптимизации: в `meta` ответа — расход хода (`calls`, токены входа/выхода/«размышлений», `ms`), токены, а не деньги: цены меняются, стоимость считается при показе; при 429 в лог — имя исчерпанного лимита (без остального текста ошибки); в промпте — несколько независимых поисков одним раундом.
- Ответ и кнопки одним вызовом `reply` (минус раунд на вопрос) отложен: меняет цикл агента и режим function calling (`ANY`), риск для тона ответа. Решать по данным `meta` о раундах и времени.
- Замер на платном тарифе (`gemini-3.6-flash`, 4 вопроса): 2–5 вызовов на вопрос, 3.6–11.7 тыс. токенов входа, 5–10 с, ~$0.008 за вопрос (с 2027 — ~$0.016). `suggestActions` всегда отдельный раунд (25–50% вызовов). «Размышления» 190–675 токенов — больше самого ответа. Оптимизация `reply` объяснена, решение — пока оставить как есть.
- Модель переключена на `gemini-3.5-flash-lite` (секрет, без деплоя): ~$0.004 за вопрос. Проверить на живом боте выбор tools (аллергены, категории).
- Баг на flash-lite (подтверждён по журналу, 11:19): «хочу бронь» → «нажмите кнопку ниже», а под ответом только «Главное меню»: модель не вызвала `suggestActions` (`calls=1`, `tools=[]`). Причина — кнопки отдельным tool: модель может пообещать кнопку и забыть её выбрать.
- Исправление: tool `reply({ text, actions })` вместо `suggestActions`, модель обязана отвечать вызовом tool (Gemini, режим `ANY`). Текст и кнопки — одно действие; ход дешевле на вызов. `reply` вместе с другими tools отклоняется (ответ до результатов — риск выдумки); пустой текст — модель отвечает снова; на последнем раунде разрешён только `reply`. `reply` в `meta.tools` не пишется — это ответ, не данные. Спека §2 (п. «Служебный tool `suggestActions`») по факту заменена — отразить в STATE при закрытии.
- Экран «Статистика AI» добавлен в спеку S09, сессия 5, и в приёмку (п.13). Баланс Gemini API — проверить в начале сессии 5, запасной вариант — ссылка на Billing.

## 2026-11-11 — S09 сессия 3: бронь и обращение диалогом
**Цель:** tools `draftBooking` и `draftGuestRequest` на общем черновике `conversations.state`, текст на шаге сценария через агента, карточка «Подтвердить» / «Отправить менеджеру» → те же `createBookingRequest` / `createGuestRequest`.
**Решения:**
- Агент не держит свой черновик: tools `draftBooking` / `draftGuestRequest` пишут тот же `BookingState` / `GuestRequestState` в `conversations.state`, что кнопки S03. Дальше работает существующий сценарий: шаги, «Назад», сводка, `submitFlow`, идемпотентность.
- Домен: `bookingDraft.ts` (`applyBookingDraft`) и `guestRequestDraft.ts`. Поля проверяются теми же валидаторами (`validateSlot`, `validateGuests`, `validateName`, `validateContact`); непрошедшее не пишется, уходит модели как ошибка поля. Шаг ставится на первое незаполненное поле: следующий ответ гостя («Анна») обрабатывает обычный шаг без LLM.
- AI-бронь вытаскивает всё из одной осмысленной фразы, данные проверяются один раз в момент вызова tool; пошаговый сценарий остаётся кнопочным, агент на шаге — только когда текст шагу не подошёл.
- Время — только целые часы (как кнопки), «19:30» отклоняется; период выводится из часа. Время без даты — ошибка `needs_date`. При отклонённом времени модель получает `freeHours` даты.
- Комментарий в AI-пути не спрашивается: черновик ставит `comment = null`, шаг контакта кнопочного сценария при решённом комментарии сразу идёт к сводке (§5 п.5: «только недостающее»).
- Изменение брони через агента: меняются только дата, время, гости; имя и контакт — `not_editable`.
- Текст на шаге: сначала обычная проверка шага; ошибка + AI включён → агент с блоком промпта «Active draft» (шаг и заполненные поля). Агент не ответил → экран шага с ошибкой, как до S09. AI выключен → как до S09.
- Шаг «имя»: эвристика `looksLikeName` (до 4 слов, без «?» и цифр), ошибка `name_unlikely`. Иначе побочный вопрос становился именем: `validateName` пропускает любой текст 2–60 символов. Сервис эвристику не применяет.

## 2026-11-12 — S09 сессия 4: голос
**Цель:** голосовые гостя через Gemini; перед этим хвосты: блюдо с `allergens = null` в seed, `pnpm eval:ai`, приёмка §5 и S06b.
**Решения:**
- `pnpm eval:ai` прогнан, расхождений нет. Приёмка S09 §5 и S06b §5 пройдена.
- Seed: «Скордалия» — опубликовано, `allergens = null`, `ingredients = null` (§5 п.3). Интеграционный тест агента проверяет, что блюдо в `notSpecified`, а не в `free`. На dev блюдо заводится через админку: seed идёт только в `db reset`.
- Распознавание — отдельный вызов Gemini «только расшифруй» (аудио inline), дальше текст идёт обычным путём роутера. Не аудио в ход агента: расшифровка нужна и вне агента (кнопка менеджера).
- Автоматически распознаётся только голос вне сценария при включённом AI — он идёт агенту. На шаге сценария и при выключенном AI гостю «напишите, пожалуйста, текстом». В ручном режиме менеджера бот молчит, как на текст.
- Каждое голосовое пишется в журнал (и отказанное, и в ручном режиме): `meta.voice = { fileId, duration, … }`. Пока текста нет, `messages.text` — заглушка «[голосовое]»; распознанный текст заменяет её, чтобы агент после возврата видел, что сказал гость.
- Менеджер слушает любое голосовое в чате админки. Аудио у нас не хранится: Edge Function по `file_id` скачивает файл у Telegram и отдаёт админке (токен бота в браузер не уходит, ретеншн S06c не меняется). Риск: срок хранения файла у Telegram не гарантирован. OGG/Opus играют Chrome и Firefox, старый Safari может не играть.
- Голос, ушедший агенту, показывается в админке с расшифровкой Gemini под плеером: распознавание всё равно оплачено, и для отладки ответа агента видно, что он услышал.
- Нераспознанное голосовое — кнопка «Распознать» в чате админки. Работает и при `ai_enabled = false`: это явное действие менеджера (нужен только ключ Gemini).
- Только `voice`; `video_note` и аудиофайлы — как раньше.
- Предел голосового менеджеру в ручном режиме — 2 минуты (`VOICE_MANAGER_MAX_SECONDS`): гость узнаёт о нём из уведомления о подключении; длиннее — просьба покороче, голосовое всё равно в журнале. Кнопку «Распознать» ограничивает только размер файла (5 МБ).
- Слои: файл скачивает обработчик (`handlers/voice.ts`, позже `manager-chat`), распознаёт `services/ai/voice.ts` по байтам — сервис про Telegram не знает (ADR-008). Проверка суточного лимита вынесена из агента в `isAiLimitReached`.
- Суточный лимит ходов распознавание не тратит, но при исчерпанном лимите голос агенту не распознаётся (ему нечем ответить) → ответ как при лимите. Кнопку менеджера лимит не ограничивает.
- Статистика: распознавание — отдельная группа рядом с ответами агента, плюс общий итог. Расход распознавания пишется в `meta` голосового сообщения.
- Гостю распознанный текст не показывается: ответ агента сам показывает, что понято.
- `meta.voice` — объект `{ fileId, duration, mimeType?, fileSize?, transcribedBy?, transcribeError?, model?, …расход }`, а не `{ voice: true, duration }` из спеки §2: нужен file_id для прослушивания и расход для статистики. Расхождение — в STATE при закрытии.
- Админка: `manager-chat` получил `voice_audio` (байты как `application/octet-stream`: `functions.invoke` отдаёт Blob только для него) и `voice_transcribe`; доступ — чтение сообщения JWT менеджера под RLS `messages_select`, запись расшифровки — service role. Подключаться к чату не нужно.
- В чате админки: «🎤 Голосовое · м:сс», «▶ Прослушать» (звук грузится по клику, в кэше RTK — blob:-URL, освобождается при удалении записи кэша), расшифровка с пометкой «для AI-помощника» / «по кнопке» либо «Распознать». Браузер не играет OGG — ссылка «Скачать». Правку сообщения Realtime не приносит (подписка только на INSERT): у другого менеджера расшифровка появится после перезагрузки ленты.
- Статистика: `ai_usage_daily` получила `source` (`agent` / `voice`) и `voice_transcribed` / `voice_failed` (миграция `20261112100000_voice_usage.sql`, drop + create). Распознавание по кнопке относится ко дню голосового, не дню нажатия. Голосовые без вызова модели (ручной режим, отказы, файл не скачан) в статистику не попадают. На экране — общая стоимость с разбивкой «ответы · голос» и блок «Распознавание голосовых»; подсказка «≈ за ответ» убрана.
- Гость узнаёт о голосе из текстов бота (`content.ts`, ADR-009): приветствие AI («можно голосовым, до минуты»), уведомление о подключении менеджера, `MANAGER_TEXT_ONLY` (голосовые менеджер слышит, стикеры и фото нет), отказы (длиннее минуты, не расслышал, текстом на шаге сценария или при выключенном AI).
