## 2026-11-11 — S09 сессия 1: данные под AI-слой
**Цель:** настройки AI ресторана, пометки сообщений и угроз, справочник аллергенов ЕС с переносом данных, выбор аллергенов в админке.
**Решения:**
- Миграция `20261111100000_ai_layer_data.sql`. `restaurant_ai_settings` (1:1, `check` на диапазоны), строку создаёт триггер на insert ресторана, существующим рестораны добавлены в миграции. RLS: менеджер только читает и правит свою строку; insert/delete нет.
- `messages.meta jsonb` (только объект или null), а не новые значения `kind`: от `kind = 'text'` зависит превью диалога (триггер S06), AI-ответ и голосовое тоже текст.
- `conversations.flagged_at` + `flag_reason` ставятся и снимаются парой (check). Снятие — RPC в сессии 5.
- Аллергены: коды латиницей, функция `eu_allergen_codes()` и check `allergens <@ eu_allergen_codes()`. Перенос по словарю синонимов; одно несопоставимое слово → всё значение блюда `null` + `raise notice`: выбросить только неизвестное слово значило бы молча убрать аллерген из карточки.
- Справочник в трёх местах (БД, бот, админка): общего модуля нет, у них разные сборки. Сверку держит RLS-тест (RPC `eu_allergen_codes` против обоих списков).
- Админка: в режиме «Указать» вместо ввода тегов 14 чекбоксов; порядок кодов всегда по справочнику. `addTag`/`removeTag` удалены. `database.types.ts` правлен вручную: генератор берёт схему с удалённой dev-БД, а миграция попадёт туда только через CI.
- Тип `MessageMeta` не заводился: впервые понадобится в сессии 2 при записи AI-ответа.
**Осталось:** миграция, seed и новые RLS-кейсы не прогонялись: локально нет Docker, а `.env` смотрит в удалённую dev-БД без миграции. Проверка — локальная БД или CI на PR.

## 2026-11-11 — S09 сессия 2: агент и вопросы по меню
**Цель:** слой `llm/` (Gemini), агент `runAgentTurn` с tools на сервисах ядра, `filterMenuByAllergens`, маршрут свободного текста агенту при `ai_enabled`, приветствие AI-помощника, деградация, суточный лимит, `messages.meta`.
**Решения:**
- Сессия 1 смержена (PR #3): `integration` на PR прогнал миграцию и RLS-тесты, deploy применил миграцию к удалённой БД без ошибок. Проверка миграции из «Осталось» сессии 1 закрыта.
- Работаем прямо в `main`, коммиты локально по этапам; push только по команде: push в `main` сразу выкатывает бота.
- Метод SDK — `generateContent` (ничего не хранит у Google, окно истории передаём сами), не Interactions API. SDK `npm:@google/genai@2.31.0`.
- Thought signatures Gemini 3 возвращаются внутри хода через непрозрачное `providerState` ответа LLM: типы Google не выходят из `llm/`. Между ходами не нужны — история идёт текстом.
- Webhook остаётся синхронным: повторная доставка при таймауте отсекается `registerUpdate`. Проверить на живом боте.
- Окно истории — сообщения `kind` `text`/`search`, без `[кнопка] …`.
- Модель: рекомендована `gemini-3.6-flash` (стабильная, бесплатный уровень, function calling); задаётся секретом `GEMINI_MODEL`.
- SDK без повторов внутри (`retryOptions.attempts = 1`): по умолчанию до 5 попыток с паузой до 60 с, это больше бюджета хода.
- Стоп-лист для AI: tools не отдают модели блюда с `is_available = false` (списки, подбор по аллергенам, карточка — `not_found`). Кнопочное меню их по-прежнему показывает с пометкой «недоступно». Приёмка §5 п.4.
- Клиент Gemini создаёт `services/ai/llm.ts`, не `index.ts`: обработчики не импортируют `llm/` (тесты и `testing/` — исключение, им нужен фейк).
- Нет `GEMINI_API_KEY`/`GEMINI_MODEL` → бот как до S09 (поиск блюда, старое приветствие), а не запасной ответ на каждый текст.
- Сбой чтения `restaurant_ai_settings` → AI считается выключенным: рубильник менеджера важнее.
- Кнопка «Карточка блюда» под ответом агента подписана названием блюда: при двух блюдах одинаковые подписи неразличимы.
- «Можно голосовым» в приветствии появится с голосом (сессия 4).
- Тесты агента — интеграционные (фейковый LLM + БД с seed), гоняются только в CI: локально нет Docker.
- В seed нет опубликованного блюда с `allergens = null` — для приёмки §5 п.3 (группа «состав не указан») нужно поправить seed или блюдо в админке.
- Первый прогон на живом боте: после 1–3 ответов — `aiFallback: "quota"` (429, бесплатный уровень, подтверждено по `messages.meta`). Один вопрос гостя = 2–6 вызовов модели (раунды tools), первый ответ — 17 с. Проект переведён на платный тариф, модель прежняя (`gemini-3.6-flash`).
- Безопасные оптимизации: в `meta` ответа — расход хода (`calls`, токены входа/выхода/«размышлений», `ms`), токены, а не деньги: цены меняются, стоимость считается при показе; при 429 в лог — имя исчерпанного лимита (без остального текста ошибки); в промпте — несколько независимых поисков одним раундом.
- Ответ и кнопки одним вызовом `reply` (минус раунд на вопрос) отложен: меняет цикл агента и режим function calling (`ANY`), риск для тона ответа. Решать по данным `meta` о раундах и времени.
**Осталось:**
- push по команде → CI → deploy; проверка на живом боте на платном тарифе: меню, аллергены, «ты бот?», стоп-лист, время ответа.
- Предложено, не решено: экран статистики в админке (ходы, токены, оценка стоимости по таблице цен с датами, причины запасных ответов, время ответа) — в спеке S09 его нет. Баланс Gemini API: простого API, вероятно, нет — проверить перед спекой.
