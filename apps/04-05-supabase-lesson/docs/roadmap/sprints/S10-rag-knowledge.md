# S10 — RAG и база знаний

Агент из S09 отвечает по документам ресторана: история, концепция, подборки («что-нибудь лёгкое»),
правила посещения. Менеджер пишет эти документы в админке.

## 1. Цель и границы

- **Входит:**
  - Документы ресторана и их публикация.
  - Векторный поиск (pgvector) по документам, FAQ и описаниям блюд.
  - Tool `searchKnowledge` для агента S09.
  - Редактор документов в админке.
  - Новый ADR вместо ADR-004 (запись «RAG не планируется» была неверной; решение о RAG принято
    2026-11-10).
- **Не входит:** загрузка PDF/сайта ресторана с автоматическим разбором (если не решим иначе в §4),
  персональные рекомендации по истории гостя.
- **Зависит от:** S09 (цикл агента, AI-режим).

## 2. Что делаем

### 2.А Схема / данные

- `knowledge_documents` — тип (история, концепция, подборка/рекомендация, правила посещения,
  события, …), заголовок, текст, опубликован ли, `restaurant_id`.
- `knowledge_chunks` — фрагменты документов с эмбеддингом (`pgvector`), ссылка на источник.
- Источники индекса: документы, FAQ, описания блюд.
- Подборки ссылаются на блюда по `menu_items.id` (§4.3).
- RLS: менеджер видит документы своего ресторана; кейсы в `rls.integration.test.ts`.
- Seed: тестовые документы для Лавраки (история, «лёгкое и рыбное», «для детей», правила).

### 2.Б Сервер

- Нарезка документов на фрагменты, получение эмбеддингов, запись в `knowledge_chunks`.
- Переиндексация при сохранении документа / FAQ / блюда в админке.
- Поиск: векторный, возможно гибридный с полнотекстовым (§4.4).
- Tool `searchKnowledge` → агент S09. Ответ со ссылкой на документ-источник.

### 2.В Экран

- Админка: список документов, редактор, публикация, статус индексации.

## 3. Инварианты, которые этот спринт обязан удержать

- **«Не выдумывать»:** ответ по документам — только из найденных фрагментов; ничего не найдено →
  «не знаю, уточните у персонала».
- **Аллергены — не через векторный поиск.** Вопрос безопасности идёт через детерминированный фильтр
  S09, даже если документ про блюдо нашёлся.
- **Подборка не предлагает недоступное:** блюда из подборки проверяются через `getDishDetails`
  в момент ответа (стоп-лист, публикация).
- Неопубликованные документы не попадают в поиск.
- Текст документов — данные, не инструкции для агента.

## 4. Открытые вопросы объёма

1. ~~Эмбеддинги.~~ **Решено 2026-11-10:** эмбеддинги Gemini (`gemini-embedding-001` или `-2` —
   выбрать в чистовике), хранение и поиск — pgvector. Документы и запросы гостей — на русском,
   без перевода. Один провайдер и ключ с S09.
   - Цена: бесплатный уровень есть; платный $0.15–0.20 за 1M токенов — для базы ресторана копейки.
   - Лимиты считаются на модель в проекте: эмбеддинги не расходуют лимит чата. Точные цифры
     бесплатного уровня — в консоли AI Studio проекта.
   - Вызовы: индексация — один запрос на сохранение документа; поиск — не больше одного запроса на
     вызов `searchKnowledge`.
   - Эмбеддинг недоступен → `searchKnowledge` возвращает «поиск недоступен», агент отвечает через
     остальные tools.
   - **Отвергнуто: `gte-small`** (встроен в Supabase Edge Runtime, бесплатный, без ключа).
     Проверено локально (transformers.js, `Supabase/gte-small`, 6 документов × 6 вопросов):
     токенизатор режет кириллицу на отдельные буквы; правильный документ на 1-м месте — EN→EN 6/6,
     RU→RU 4/6 (совпадение букв, не смысл; разброс оценок в 2–3 раза меньше), RU-вопрос→EN-документы
     2/6. Работает только с английским индексом и переводом запроса агентом; тогда нужны английские
     копии документов, а их автоперевод — те же вызовы Gemini. Проще сразу многоязычные эмбеддинги.
   - Другие провайдеры по API (OpenAI, Voyage, Cohere, Jina) — второй ключ без выигрыша; своя
     многоязычная модель в Edge Function — неподдерживаемый Supabase путь (только `gte-small`).
2. **Как менеджер пишет документы:** редактор в админке, загрузка файла, оба.
3. **Подборки:** ссылки на блюда по `id` (рекомендация) или только описание идеи, а блюда подбирает
   `searchMenu`.
4. **Поиск:** только векторный или гибридный (вектор + полнотекстовый).
5. **Переиндексация:** синхронно при сохранении или по паттерну Supabase «автоматические эмбеддинги»
   (триггер/Database Webhook → Edge Function считает вектор → запись в таблицу).
6. **Нарезка:** фрагмент — 2–3 абзаца; перекрытие нужно ли; короткие документы — целиком.
