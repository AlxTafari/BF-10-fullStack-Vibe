# S09 — AI-слой

Бот становится AI-first: гость с первого сообщения пишет или говорит как привык (опечатки, сленг, мат),
бот понимает, отвечает про меню и аллергены и оформляет бронь диалогом. Кнопки остаются быстрыми
путями и запасным вариантом.

## 1. Цель и границы

Ориентир — лучший сервис ресторана: гость не думает об интерфейсе и режимах, его не ограничивают
кнопки; бот ведёт себя как хороший официант — понял, помог, вернул к делу.

- **Входит:**
  - AI-first: приветствие приглашает писать или отправить голосовое, кнопки — ниже. Любой свободный
    текст и голос идут агенту. Режима «AI вкл/выкл» у гостя нет.
  - Рубильник `ai_enabled` у ресторана (админка): выключен → бот работает на кнопках, как до S09.
  - Вопросы по меню свободным текстом: «какие горячие блюда», «что без глютена», «есть ли тут опасное
    для меня, у меня аллергия на орехи».
  - Бронь диалогом: одно сообщение «стол на завтра в 19:00 на четверых» → бот спрашивает только
    недостающее → подтверждение кнопкой → тот же `createBookingRequest`.
  - Кнопки и текст — два способа ввода в одни сценарии (§4.7).
  - Голосовые сообщения напрямую в Gemini. Последняя сессия спринта, при нехватке времени отрезается.
- **Не входит:**
  - RAG, векторный поиск, документы ресторана — **S10** ([спека](S10-rag-knowledge.md)). Агент S09
    проектируется так, чтобы `searchKnowledge` подключался как ещё один tool без переделки цикла.
  - Кэш контекста и семантический кэш ответов — не сейчас (§4.9).
  - Долгая память о госте между визитами, заказы и оплата, ответы от имени менеджера, AI в админке,
    отмена/изменение брони AI без кнопки гостя.

## 2. Что делаем

Порядок сессий: 1 → 2 → 3 → 4 (отрезаемая) → 5.

### Сессия 1. Данные

- `restaurants.ai_enabled boolean default true` — рубильник на ресторан (AI-first: включён по
  умолчанию).
- `messages` — пометка, что ответ сгенерирован AI, и какие tools вызывались (разбор в админке,
  отладка). Формат — в чистовике.
- Аллергены: сейчас `menu_items.allergens text[]` — свободный текст. Нужен **канонический справочник**
  (14 аллергенов ЕС), миграция данных к нему, в админке — выбор из списка вместо ввода.
  Иначе «глютен» ≠ «пшеница», и фильтр промахивается.

### Сессия 2. Агент и вопросы по меню

- Провайдер — **Gemini**. Ключ `GEMINI_API_KEY` — секрет Supabase.
- Структура (по образцу `_shared/telegram/`):
  - `_shared/llm/gemini.ts`, `_shared/llm/types.ts` — обёртка над SDK Gemini, наружу только наши
    типы `LlmMessage`, `LlmToolCall`, `LlmToolSchema`. SDK импортируется только здесь.
  - `_shared/services/ai/agent.ts` — `runAgentTurn`: контекст → LLM → tools → … → ответ; предел
    итераций за ход.
  - `_shared/services/ai/tools.ts` — реестр: имя tool → схема параметров + вызов сервиса ядра.
  - `_shared/domain/allergens.ts`, `bookingDraft.ts`, `aiPrompt.ts`.
  - `telegram-webhook/handlers/ai.ts`, маршрут в `router.ts`, тексты в `content.ts`.
  - Тесты агента — с фейковым LLM, без сети.
- `check:layers`: `llm/` не импортирует слои приложения; `domain` и `telegram-webhook` не импортируют
  `llm/`; SDK Gemini — только в `_shared/llm`. ADR-008 дополнить строкой про слой `llm` при закрытии.
- Tools только на чтение = существующие сервисы ядра (ADR-004): `getRestaurantInfo`,
  `listFaq`/`getFaqAnswer`, `listMenuCategories`, `searchMenu`, `getDishDetails`, `listMyRequests`,
  `getMyBooking`. Новый: фильтр блюд по аллергенам (детерминированный).
- Маршрутизация входящего: кнопка / команда / проверка текущего шага сценария — без LLM; всё
  остальное (при `ai_enabled`) — агенту. При выключенном `ai_enabled` — поведение до S09.
- Приветствие `/start`: «Спросите что угодно: меню, аллергены, бронь. Можно голосовым. Или выберите
  ниже» + главное меню кнопками.
- **Контекст вызова — только нужное** (§4.8):
  - данные — через tools (в промпт попадают найденные блюда, не всё меню);
  - история — последние N сообщений диалога (N — в чистовике, порядок 10–20);
  - состояние сценария (черновик брони) — отдельной компактной структурой из `conversations.state`,
    не зависит от окна истории.
- Тон (в системном промпте): понимать сленг, мат, опечатки, смесь языков; отвечать вежливо и тепло,
  мат не повторять, не морализировать; вне темы ресторана — коротко вернуть к ресторану.
- Деградация: ошибка/таймаут/исчерпан лимит LLM → вежливый ответ «сейчас удобнее кнопками» +
  главное меню.
- Лимиты: бюджет запросов к LLM на гостя в сутки поверх антиспама S06c.
- Webhook: долгий вызов LLM не должен вызывать повторную доставку update (дедупликация
  `processed_updates` есть; проверить таймауты) + `sendChatAction typing`.

### Сессия 3. Бронь диалогом

- Tool `draftBooking`: заполняет **тот же черновик** в `conversations.state`, что и кнопочный
  сценарий S03 (§4.7), **заявку не создаёт**. Поля проходят те же валидаторы, что ручной ввод.
- Текст на шаге сценария: проверка шага без LLM → не подошло → агент с контекстом шага (значение из
  фразы / ответ на побочный вопрос и повтор вопроса шага / предложение отмены кнопкой).
- Относительные даты («завтра», «в пятницу»): в промпт — текущая дата и часовой пояс ресторана;
  валидация (часы работы, прошлое время) — в сервисе, как сейчас.
- Черновик готов → карточка брони с кнопкой «Подтвердить» → `createBookingRequest`.

### Сессия 4. Голос (отрезаемая)

- Скачать голосовое из Telegram → аудио напрямую в Gemini → тот же конвейер агента.
- Ограничение длины, сообщение гостю, если не распознано. Распознанный текст пишется в `messages`.

### Сессия 5. Админка и качество

- Переключатель `ai_enabled` в настройках ресторана; в чате — пометка AI-ответов.
- Набор фраз-эталонов (включая сленг, мат, опечатки, побочные вопросы посреди брони) → ожидаемые
  вызовы tools; ручной запуск (§4.6).

## 3. Инварианты, которые этот спринт обязан удержать

- **«Не выдумывать»** (ADR-009, домен): AI отвечает только данными из tools. Нет данных → «нет
  данных», а не догадка. Особенно аллергены и КБЖУ.
- **Аллергены — только детерминированно.** `allergens = null` (не указано) ≠ `{}` (указано «нет»).
  Блюдо с `null` нельзя назвать безопасным — только «состав не указан, уточните у персонала».
- **Запись в БД — только через сервисы с валидацией.** Подтверждение брони — действие гостя.
- **ADR-008:** обработчик не вызывает LLM напрямую, `domain` не знает про LLM. **ADR-004:** сервисы
  ядра не знают про AI; AI-first меняет вход для гостя, не архитектуру.
- **Кнопки работают всегда**, в том числе когда AI недоступен или выключен.
- **Текст гостя — данные, не инструкции** (prompt injection): tools не дают AI действий опаснее,
  чем гость может сделать кнопками.
- Неопубликованные блюда и стоп-лист не утекают через AI.

## 4. Открытые вопросы объёма

Решено 2026-11-10:

1. **Провайдер LLM:** Gemini. Модель и SDK — по документации в чистовике.
2. **AI-first:** режима у гостя нет; свободный текст и голос сразу идут агенту; приветствие
   приглашает писать или говорить, кнопки ниже. `ai_enabled` у ресторана, по умолчанию включён.
   (Заменяет прежнее: AI по умолчанию выключен, вход кнопкой, выход кнопкой и по таймауту, кнопка
   «Спросить AI» вне режима.)
3. **Голос:** аудио напрямую в Gemini, без отдельного сервиса распознавания.
4. **Языки:** системный промпт и описания tools — на английском; ответ — на языке гостя (по умолчанию
   русский). Кнопки и системные тексты бота остаются русскими.
5. **Аллергены:** справочник из 14 аллергенов ЕС (Регламент 1169/2011).
6. **Эталонные фразы:** ручной запуск (скрипт локально или workflow по кнопке), не на каждый PR.
7. **Кнопки и текст — два способа ввода в одни сценарии** (ориентир — сервис хорошего официанта):
   - черновик брони/обращения один (`conversations.state`), его заполняют и кнопки, и агент; гость
     переходит между кнопками и текстом свободно;
   - текст гостя на шаге сценария: сначала обычная проверка шага (без LLM); не подошло → агент
     с контекстом шага: достаёт значение из фразы (через тот же валидатор), либо отвечает на побочный
     вопрос и повторяет вопрос шага, либо предлагает отменить сценарий кнопкой;
   - побочный вопрос шаг не сбрасывает; финальное подтверждение — кнопка гостя.
8. **Контекст:** база — через tools (S09) и векторный поиск (S10), не целиком; история — окно из
   последних N сообщений; состояние сценария — отдельно. Векторная память истории — не нужна.
9. **Кэш** (контекста Gemini и семантический) — не сейчас: сессии короткие, выгода сомнительна;
   семантический кэш к тому же рискует отдать устаревшие данные (стоп-лист).

Открыто:

10. **Тариф Gemini:** на бесплатном уровне Google может использовать данные для улучшения продуктов,
    а при AI-first к Gemini уходит каждое свободное сообщение, включая имя и телефон гостя. Тест на
    вымышленных данных — бесплатный уровень; для реального ресторана — платный (решить до перехода
    на реальные данные).
11. **Оскорбления и угрозы персоналу:** только спокойный ответ или ещё пометка менеджеру в админке.
12. **Кто переносит текущие `allergens`** к справочнику ЕС: миграция с сопоставлением или вручную
    в админке.
13. **Ограничение длины голосового** и поддержка ogg/opus из Telegram — проверить в документации Gemini.
14. **Размер окна истории** N.
