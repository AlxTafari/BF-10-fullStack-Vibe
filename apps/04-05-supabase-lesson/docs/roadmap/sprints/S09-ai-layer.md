# S09 — AI-слой

Бот становится AI-first: гость с первого сообщения пишет или говорит как привык (опечатки, сленг, мат),
бот понимает, отвечает про меню и аллергены, оформляет бронь и обращение диалогом. Кнопки остаются
быстрыми путями и запасным вариантом.

## 1. Цель и границы

Ориентир — лучший сервис ресторана: гость не думает об интерфейсе и режимах, его не ограничивают
кнопки; бот ведёт себя как хороший официант — понял, помог, предложил следующий шаг, вернул к делу,
позвал человека, когда сам не может.

- **Входит:**
  - AI-first: приветствие представляет AI-помощника и приглашает писать или отправить голосовое,
    кнопки — ниже. Любой свободный текст и голос идут агенту. Режима «AI вкл/выкл» у гостя нет.
  - Настройки AI ресторана в админке: рубильник `ai_enabled`, окно истории, суточный лимит на гостя
    (§4.15). Выключен → бот работает на кнопках, как до S09.
  - Вопросы по меню свободным текстом: «какие горячие блюда», «что без глютена», «есть ли тут опасное
    для меня, у меня аллергия на орехи».
  - Бронь диалогом: одно сообщение «стол на завтра в 19:00 на четверых» → бот спрашивает только
    недостающее → карточка с кнопкой «Подтвердить» → тот же `createBookingRequest`.
  - Выход на человека: «позовите менеджера», жалоба, вопрос без данных → черновик обращения →
    кнопка гостя → тот же `createGuestRequest` (§4.16).
  - Кнопки-подсказки под ответом агента по смыслу ответа (§4.17).
  - Пометка менеджеру при угрозах персоналу (§4.11).
  - Кнопки и текст — два способа ввода в одни сценарии (§4.7).
  - Голосовые сообщения напрямую в Gemini. Последняя сессия спринта, при нехватке времени отрезается.
- **Не входит:**
  - RAG, векторный поиск, документы ресторана и их редактор в админке — **S10**
    ([спека](S10-rag-knowledge.md)). Агент S09 проектируется так, чтобы `searchKnowledge` подключался
    как ещё один tool без переделки цикла.
  - Кэш контекста и семантический кэш ответов — не сейчас (§4.9).
  - Ответы менеджера гостю в чате (S06b), долгая память о госте между визитами, заказы и оплата,
    AI в админке, отмена/изменение брони AI без кнопки гостя.
  - Настройки модели, temperature, тона и свободный текст инструкций в админке (§4.15).

## 2. Что делаем

Порядок сессий: 1 → 2 → 3 → 4 (отрезаемая) → 5.

### Сессия 1. Данные

- `restaurant_ai_settings` — настройки AI, 1:1 с `restaurants` (`restaurant_id` — первичный ключ
  и внешний ключ). Поля с `check` (диапазоны проверяет БД, поэтому не jsonb):
  - `ai_enabled boolean not null default true` — AI-first включён по умолчанию;
  - `history_window int not null default 12 check (between 4 and 30)` — окно истории N;
  - `daily_turn_limit int not null default 50 check (between 5 and 500)` — ходов агента на гостя
    в сутки.
  Строка создаётся для каждого ресторана (миграция для существующих + seed). Нет строки → сервис
  берёт значения по умолчанию из домена, не падает.
- `messages.meta jsonb null` — служебная пометка сообщения. Исходящее от AI:
  `{ "ai": true, "model": "…", "tools": ["searchMenu", …] }`. Входящее голосовое:
  `{ "voice": true, "duration": 12 }`, в `text` — распознанный текст. `null` — обычное сообщение.
  Форма `meta` — тип в `_shared/types.ts`, разбор — в домене.
- `conversations.flagged_at timestamptz null`, `conversations.flag_reason text null` — пометка
  менеджеру об угрозе (§4.11).
- Аллергены — **канонический справочник** 14 аллергенов ЕС (Регламент 1169/2011):
  - коды — константа в `_shared/domain/allergens.ts` (`cereals_gluten`, `crustaceans`, `eggs`, `fish`,
    `peanuts`, `soybeans`, `milk`, `nuts`, `celery`, `mustard`, `sesame`, `sulphites`, `lupin`,
    `molluscs`) + русские подписи; в БД — `check`, что каждый элемент `allergens` из этого списка;
  - миграция данных со словарём синонимов (глютен/пшеница → `cereals_gluten`, молоко → `milk` …).
    Несопоставимое слово блюдо **не делает безопасным**: значение становится `null` («не указано»),
    блюдо попадает в `raise notice` миграции. Семантика `null` ≠ `{}` сохраняется;
  - в админке — выбор из списка (чекбоксы) вместо ввода, с явным «аллергенов нет» (`{}`) отдельно от
    «не указано» (`null`).
- RLS для `restaurant_ai_settings` и новых колонок — по образцу существующих таблиц; кейсы в
  `rls.integration.test.ts`.

### Сессия 2. Агент и вопросы по меню

- Провайдер — **Gemini**, SDK `@google/genai`. Ключ `GEMINI_API_KEY` и модель `GEMINI_MODEL` —
  секреты Supabase (смена модели без деплоя кода). Модель — класс Flash с function calling. Правило
  выбора модели для реальных данных — §4.10.
- Вызовы без хранения на стороне Google: историю держим сами (`messages`), каждый вызов передаёт окно
  целиком. Конкретный метод SDK (`generateContent` или Interactions с `store: false`) — по документации
  в начале сессии.
- Структура (по образцу `_shared/telegram/`):
  - `_shared/llm/gemini.ts`, `_shared/llm/types.ts` — обёртка над SDK, наружу только наши типы
    `LlmMessage`, `LlmToolCall`, `LlmToolSchema`. SDK импортируется только здесь.
  - `_shared/services/ai/agent.ts` — `runAgentTurn`: контекст → LLM → tools → … → ответ; не больше
    5 раундов tools за ход, таймаут одного вызова LLM 20 с, всего хода — 45 с.
  - `_shared/services/ai/tools.ts` — реестр: имя tool → схема параметров + вызов сервиса ядра.
  - `_shared/services/aiSettings.ts` — чтение настроек ресторана с дефолтами.
  - `_shared/domain/allergens.ts`, `bookingDraft.ts`, `aiPrompt.ts`, `aiSuggestions.ts`.
  - `telegram-webhook/handlers/ai.ts`, маршрут в `router.ts`, тексты в `content.ts`.
  - Тесты агента — с фейковым LLM, без сети.
- `check:layers`: `llm/` не импортирует слои приложения; `domain` и `telegram-webhook` не импортируют
  `llm/`; SDK Gemini — только в `_shared/llm`.
- Tools на чтение = существующие сервисы ядра (ADR-004): `getRestaurantInfo`,
  `listFaq`/`getFaqAnswer`, `listMenuCategories`, `searchMenu`, `getDishDetails`, `listMyRequests`,
  `getMyBooking`. Новый: `filterMenuByAllergens` — детерминированный, по кодам справочника; делит
  блюда на «без указанных аллергенов», «содержит», «состав не указан».
- Служебный tool `suggestActions` — кнопки под ответом (§4.17).
- Маршрутизация входящего: кнопка / команда / проверка текущего шага сценария — без LLM; всё
  остальное (при `ai_enabled`) — агенту. При выключенном `ai_enabled` — поведение до S09.
- Приветствие `/start` (в `content.ts`): «Я AI-помощник ресторана «…». Спросите что угодно: меню,
  аллергены, бронь. Можно голосовым. Или выберите ниже» + главное меню кнопками. На вопрос «ты бот?»
  агент отвечает честно (правило в промпте).
- **Контекст вызова — только нужное** (§4.8):
  - данные — через tools (в промпт попадают найденные блюда, не всё меню);
  - история — последние `history_window` сообщений диалога из `messages`;
  - состояние сценария (черновик брони/обращения) — отдельной компактной структурой из
    `conversations.state`, не зависит от окна истории;
  - текущая дата, время и часовой пояс ресторана.
- Системный промпт и описания tools — на английском, ответ — на языке гостя. Тон фиксирован: на «вы»,
  тепло и коротко; понимать сленг, мат, опечатки, смесь языков; мат не повторять, не морализировать;
  вне темы ресторана — коротко вернуть к ресторану.
- Ответ агента пишется в `messages` с `meta.ai`.
- Деградация: ошибка / таймаут / превышен `daily_turn_limit` / исчерпана квота Gemini → вежливый ответ
  «сейчас удобнее кнопками» + главное меню. Гость не видит текста ошибки.
- Лимит: ходы агента считаются по исходящим `messages` с `meta.ai` за текущие сутки в часовом поясе
  ресторана; поверх антиспама S06c, отдельной таблицы нет.
- Webhook: долгий вызов LLM не должен вызывать повторную доставку update (дедупликация
  `processed_updates` есть; проверить поведение при таймауте) + `sendChatAction typing` перед вызовом.

### Сессия 3. Бронь и обращение диалогом

- Tool `draftBooking`: заполняет **тот же черновик** в `conversations.state`, что и кнопочный
  сценарий S03 (§4.7), **заявку не создаёт**. Поля проходят те же валидаторы, что ручной ввод.
- Tool `draftGuestRequest`: так же для обращения — тема и текст из фразы гостя, контакт — по правилам
  сценария S03. Агент предлагает его, когда гость просит человека, жалуется или на вопрос нет данных.
- Текст на шаге сценария: проверка шага без LLM → не подошло → агент с контекстом шага (значение из
  фразы / ответ на побочный вопрос и повтор вопроса шага / предложение отмены кнопкой).
- Относительные даты («завтра», «в пятницу»): разбирает агент по дате в промпте; валидация (часы
  работы, прошлое время) — в сервисе, как сейчас.
- Черновик готов → карточка с кнопкой «Подтвердить» / «Отправить менеджеру» →
  `createBookingRequest` / `createGuestRequest`.

### Сессия 4. Голос (отрезаемая)

- Скачать голосовое из Telegram (`getFile`, OGG/Opus) → аудио inline в Gemini → тот же конвейер агента.
- Длина до 60 с — константа в домене, проверка по `voice.duration` до скачивания. Длиннее → «Запишите,
  пожалуйста, покороче или напишите текстом». Не распознано → просьба повторить или написать.
- Распознанный текст пишется во входящее сообщение (`meta.voice`), в админке виден как текст
  с пометкой голоса.

### Сессия 5. Админка и качество

- Экран настроек ресторана: блок «AI-помощник» — `ai_enabled`, окно истории, суточный лимит
  (подсказки к полям, диапазоны как в `check`).
- Чат: пометка AI-ответов и голосовых сообщений (из `meta`); бейдж «угроза» у помеченного диалога
  в списке чатов, причина в чате, кнопка «Разобрано» снимает пометку.
- Набор фраз-эталонов (сленг, мат, опечатки, побочные вопросы посреди брони, «позовите человека»,
  угроза, попытка prompt injection) → ожидаемые вызовы tools; ручной запуск (§4.6).
- Экран «Статистика AI» (добавлено 2026-11-11): за день / неделю / месяц — ходы агента, токены
  (вход, выход, «размышления»), оценка стоимости, запасные ответы по причинам (`quota`, `timeout`,
  `error`, `limit`), среднее время ответа. Источник — расход хода в `messages.meta` (пишется с сессии 2).
  Храним токены, деньги считаются при показе по таблице цен модели с датами действия (цены меняются).
  Баланс Gemini API: простого API, вероятно, нет — проверить в начале сессии; запасной вариант — ссылка
  на Billing в AI Studio.

## 3. Инварианты, которые этот спринт обязан удержать

- **«Не выдумывать»** (ADR-009, домен): AI отвечает только данными из tools. Нет данных → «нет
  данных» и предложение спросить менеджера, а не догадка. Особенно аллергены и КБЖУ.
- **Аллергены — только детерминированно.** `allergens = null` (не указано) ≠ `{}` (указано «нет»).
  Блюдо с `null` нельзя назвать безопасным — только «состав не указан, уточните у персонала».
- **Запись в БД — только через сервисы с валидацией.** Создание брони и обращения — кнопка гостя.
  Пометка угрозы — единственная запись по решению агента, она ничего не делает от имени гостя.
- **ADR-008:** обработчик не вызывает LLM напрямую, `domain` не знает про LLM. **ADR-004:** сервисы
  ядра не знают про AI; AI-first меняет вход для гостя, не архитектуру.
- **Кнопки работают всегда**, в том числе когда AI недоступен, выключен или лимит исчерпан.
- **Текст гостя — данные, не инструкции** (prompt injection): tools не дают AI действий опаснее,
  чем гость может сделать кнопками. Кнопки-подсказки — только из фиксированного набора.
- Неопубликованные блюда и стоп-лист не утекают через AI.
- **Гость знает, что говорит с AI** (приветствие, честный ответ на прямой вопрос).
- **Реальные данные гостей — только на тарифе без обучения на данных** (§4.10).

## 4. Решения по объёму

Решено 2026-11-10:

1. **Провайдер LLM:** Gemini, SDK `@google/genai`, модель — секрет `GEMINI_MODEL`.
2. **AI-first:** режима у гостя нет; свободный текст и голос сразу идут агенту; приветствие
   приглашает писать или говорить, кнопки ниже. `ai_enabled` у ресторана, по умолчанию включён.
3. **Голос:** аудио напрямую в Gemini, без отдельного сервиса распознавания.
4. **Языки:** системный промпт и описания tools — на английском; ответ — на языке гостя (по умолчанию
   русский). Кнопки и системные тексты бота остаются русскими.
5. **Аллергены:** справочник из 14 аллергенов ЕС (Регламент 1169/2011).
6. **Эталонные фразы:** ручной запуск (скрипт локально или workflow по кнопке), не на каждый PR.
7. **Кнопки и текст — два способа ввода в одни сценарии** (ориентир — сервис хорошего официанта):
   - черновик брони/обращения один (`conversations.state`), его заполняют и кнопки, и агент; гость
     переходит между кнопками и текстом свободно;
   - текст гостя на шаге сценария: сначала обычная проверка шага (без LLM); не подошло → агент
     с контекстом шага: достаёт значение из фразы (через тот же валидатор), либо отвечает на побочный
     вопрос и повторяет вопрос шага, либо предлагает отменить сценарий кнопкой;
   - побочный вопрос шаг не сбрасывает; финальное подтверждение — кнопка гостя.
8. **Контекст:** база — через tools (S09) и векторный поиск (S10), не целиком; история — окно из
   последних N сообщений; состояние сценария — отдельно. Векторная память истории — не нужна.
9. **Кэш** (контекста Gemini и семантический) — не сейчас: сессии короткие, выгода сомнительна;
   семантический кэш к тому же рискует отдать устаревшие данные (стоп-лист).
10. **Тариф Gemini:** разработка и приёмка — бесплатный уровень на вымышленных данных. До первого
    реального гостя — обязательный шаг: платный тариф **и** модель, у которой в прайсе платного уровня
    «Used to improve our products: No» (у части моделей там «Yes» даже на платном уровне). Шаг
    записывается в `STATE.md` §4 как условие запуска.
11. **Оскорбления и угрозы:** мат и грубость — спокойный ответ, без пометок. Явная угроза персоналу
    или ресторану (насилие, порча имущества) — спокойный ответ + tool `flagThreat({ reason })` →
    `conversations.flagged_at`/`flag_reason` → бейдж в админке. Сомнение → не помечать (ложная пометка
    на сленг хуже пропуска: переписка и так видна в чате).
12. **Перенос текущих `allergens`:** миграция со словарём синонимов; несопоставимое → `null` + список
    в выводе миграции.
13. **Голосовое:** Gemini принимает `audio/ogg` и `audio/opus` (документация Gemini API, Audio
    understanding), 32 токена на секунду, предел запроса 20 МБ. Ограничение — 60 с, константа.
14. **Окно истории:** N = 12 по умолчанию, настраивается в админке (§4.15).
15. **Настройки в админке:** `ai_enabled`, окно истории (4–30), суточный лимит ходов на гостя (5–500).
    Не выносятся: модель и temperature (менеджеру не о чём, модель связана с тарифом §4.10), свободный
    текст инструкций (одна строка ломает «не выдумывать»; факты о ресторане — база знаний S10), тон
    и голос (константы), тексты бота (ADR-009). Хранение — `restaurant_ai_settings` с `check`.
16. **Выход на человека:** tool `draftGuestRequest` заполняет черновик обращения из фразы гостя →
    карточка «Отправить менеджеру» → `createGuestRequest` по кнопке. Не номер телефона вместо
    обращения: ресторан должен видеть проблему в админке.
17. **Кнопки под ответом:** агент выбирает до 3 действий через `suggestActions` из фиксированного
    набора: «Забронировать стол», «Карточка блюда» (id проверяется: блюдо существует и опубликовано),
    «Меню», «Мои заявки», «Написать менеджеру», «Главное меню». Кнопки — существующие callback'и,
    подписи — из `content.ts`. Не вызвал — под ответом «Главное меню».
18. **Прозрачность:** гость узнаёт про AI в приветствии один раз; на прямой вопрос агент отвечает
    честно; без пометок в каждом ответе (EU AI Act, ст. 50).
19. **ADR при закрытии:** новый ADR-010 «AI-слой: Gemini, агент поверх сервисов ядра»; ADR-004 —
    статус «реализовано S09», выбор провайдера закрыт; ADR-008 — строка про слой `llm`; ADR-009 —
    исключение: текст ответа агента генерирует модель, системные реплики (приветствие, деградация,
    подписи кнопок) по-прежнему в `content.ts`.

## 5. Что показываем на приёмке

На вымышленных данных, бесплатный уровень Gemini.

1. `/start` → приветствие AI-помощника, приглашение писать/говорить, кнопки ниже.
2. «че есть горячего?» → горячие блюда из меню, кнопки «Карточка блюда» / «Забронировать стол».
3. «у меня аллергия на орехи, что можно?» → три группы: без орехов / содержит / состав не указан
   (блюда с `null` не попадают в «можно»).
