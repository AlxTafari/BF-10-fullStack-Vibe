# S02 — Информация и меню

После спринта гость через кнопки читает FAQ, листает меню (категории → блюда → карточка с ценой, составом, аллергенами, порцией и КБЖУ) и находит блюдо, написав его название. Чего нет в БД — бот так и говорит: «нет данных», ничего не выдумывает. AI нет (ADR-004).

## 1. Цель и границы

- **Входит:** FAQ (список вопросов → ответ), меню (категории → блюда → карточка), поиск блюда по названию текстом, уточнение при нескольких совпадениях, обработка «нет данных», пометка блюд в стоп-листе, навигация «назад» на каждом экране. Сервисы ядра `searchMenu` и `getDishDetails` (ADR-004), `listFaq`.
- **Не входит:** бронь и обращения (S03; их кнопки остаются заглушками), подбор по пожеланиям и бюджету (S09), поиск по описанию/составу, правка меню (S04), миграции схемы (все таблицы есть с S01).

## 2. Что делаем

### 2.А Схема / данные
Миграций нет — `faq_entries`, `menu_categories`, `menu_items` заведены в S01.

- Seed уже содержит нужные граничные случаи: тарамасалата и осьминог без КБЖУ, тарамасалата без состава, креветки в стоп-листе (`is_available = false`), «Рыба дня» неопубликована, у дорады `carbs = 0.0`. Если для приёмки не хватает случая (например блюдо без категории, блюдо с `allergens = '{}'`) — добавить в `seed.sql` идемпотентно, как остальное.
- Выборки только по `is_published = true` и `restaurant_id` — фильтр в репозитории (SQL), не в обработчике и не в домене.

### 2.Б Сервер

**Репозитории** (`_shared/repositories`):
- `faqRepo` — `listPublished(restaurantId)` по `sort_order`; `getPublished(restaurantId, faqId)`.
- `menuRepo` — `listCategoriesWithItems(restaurantId)` (только категории, где есть опубликованные блюда), `listItemsByCategory(restaurantId, categoryId)`, `getPublishedItem(restaurantId, itemId)`, `searchPublishedByName(restaurantId, query, limit)`.

**Домен** (`_shared/domain`, чистые функции + `deno test`):
- `formatPrice(price, currency)` → «6,50 €». Неизвестный код валюты не должен ронять форматирование (`Intl` кидает `RangeError`) — запасной вариант «6.50 XYZ».
- `formatDishCard(item)` → текст карточки (см. ниже). Единственное место, где решается «нет данных» для блюда.
- `normalizeSearchQuery(raw)` → `string | null`: trim, схлопнуть пробелы, длина 2–50, иначе `null`. Экранирует `%`, `_`, `\` для `ilike` — иначе запрос «%» вернёт всё меню.
- Константа `NO_DATA` уже есть в `formatRestaurantInfo.ts` — переиспользовать, не заводить второй текст.

Карточка блюда:
```
Дорада на гриле — 24,00 €
Цельная дорада на углях с лимоном и оливковым маслом.

Состав: дорада, лимон, оливковое масло, орегано
Аллергены: рыба
Порция: 450 г
КБЖУ на порцию: 420 ккал · Б 52 · Ж 22 · У 0

⚠️ При аллергии уточните состав у персонала: данные в карточке могут быть неполными.
```
- Нет значения (`null`) → «нет данных — уточните у персонала». **Ноль — это значение**, показывается как `0`. Нет ни одного из четырёх КБЖУ — одна строка «КБЖУ на порцию: нет данных…»; частично заполнено — пропущенные поля как «—».
- `allergens`: `null` → «нет данных»; `[]` → «нет (по данным карточки)»; иначе список. Предупреждение про аллергию — **всегда**, на любой карточке.
- `is_available = false` → первой строкой «⏸ Сейчас недоступно». Блюдо остаётся видимым (гость должен понять, что оно есть, но заказать нельзя).

**Сервисы** (`_shared/services`, сигнатуры пригодны под tool-calling, ADR-004):
- `listFaq(client)` → `{ id, question }[]`; `getFaqAnswer(client, { faqId })` → `{ question, answer } | null`.
- `listMenuCategories(client)` → категории с блюдами.
- `searchMenu(client, { query?, categoryId? })` → `DishSummary[]` (id, name, price, currency, isAvailable), не больше `SEARCH_LIMIT = 8`; `query` проходит `normalizeSearchQuery` внутри сервиса, невалидный — пустой результат с причиной (`too_short`), не исключение. Без `maxPrice` — подбор по бюджету это S09.
- `getDishDetails(client, { dishId })` → карточка `| null`. Неопубликованное блюдо = `null`, как несуществующее.
- Ресторан сервисы берут из `restaurants` так же, как `getRestaurantInfo` (один ресторан в MVP); `restaurantId` в публичные аргументы не выносим.

**Обработчики и роутер** (`telegram-webhook`):
- Новые `callback_data` (лимит Telegram — 64 байта; `префикс:uuid` = ~40, укладываемся):
  `faq:list`, `faq:<uuid>`, `menu:cats` (уже есть как `menu:menu`), `cat:<uuid>`, `dish:<uuid>`.
- Разбор `callback_data` — чистая функция в `content.ts`/домене (`parseCallback(data) → { kind, id? } | null`), не цепочка `startsWith` в роутере. Неизвестное/битое значение → тихий возврат в главное меню, не ошибка.
- `handlers/faq.ts`, `handlers/menu.ts`, `handlers/search.ts` — тонкие: разобрать апдейт → сервис → `reply`.
- Свободный текст теперь = поиск по названию. 0 результатов → «Не нашёл такого блюда» + кнопки «Меню» и «Главное меню»; 1 → сразу карточка; 2–8 → кнопки выбора («Уточните, какое блюдо»); больше `SEARCH_LIMIT` → первые 8 + «Найдено больше, уточните запрос».
- Клавиатуры: на каждом экране «← Назад» на уровень выше и «🏠 Главное меню». Тупиков нет.
- Новое сообщение на каждый шаг (не `editMessageText`) — все реплики попадают в `messages` и видны в чате админки S06. См. вопрос 1.
- `FREE_TEXT_HINT` и `SECTION_STUB` в `content.ts` обновить: заглушки остаются только у брони и менеджера.

### 2.В Экран
Экрана админки нет — «экран» = чат в Telegram. Дерево:

```
/start → главное меню
  ├─ ℹ️ О ресторане          (S01)
  ├─ ❓ Частые вопросы → список вопросов → ответ → [← К вопросам] [🏠]
  ├─ 🍽 Меню → категории → блюда категории → карточка → [← В «Мезе»] [🏠]
  └─ текст «осьминог» → карточка / выбор из совпадений / «не нашёл»
```

## 3. Инварианты, которые этот спринт обязан удержать

- Бот не выдумывает данные: отсутствие значения → «нет данных — уточните у персонала». Ноль не путать с `null` (`if (value)` теряет `0` — проверять `=== null`). См. `domain-model.md`, MVP-план §4.1.
- Не рекомендовать недоступное блюдо как доступное — пометка «Сейчас недоступно» везде, где блюдо показано (список, поиск, карточка).
- Отсутствие аллергена в карточке — не гарантия безопасности; предупреждение на каждой карточке.
- Гостю недоступны неопубликованные блюда **и по прямому `callback_data`**: `dish:<uuid>` с чужим/скрытым id обрабатывается как «не найдено». Нельзя полагаться на то, что кнопки не будет — её можно подделать.
- Внутренние поля (`external_id`, `source`, `source_updated_at`, `restaurant_id`, `photo_url` пока не нужен) в ответ не попадают — сервис возвращает явный тип, а не `select *` как есть.
- Слои по ADR-008: обработчики не ходят в репозитории; `pnpm check:layers` зелёный.

## 4. Открытые вопросы объёма

Вопрос без ответа блокирует связанную задачу — ответ даётся первой записью `QA.md` сессии.

1. **Новое сообщение или правка предыдущего (`editMessageText`)?** Рекомендация: новое сообщение — проще и каждая реплика остаётся в `messages`; цена — длинная лента в чате. Блокирует: сигнатуру `TelegramClient`.
2. **Блюда без категории (`category_id is null`)?** Рекомендация: в списке категорий не показываем, находятся только поиском. Альтернатива — виртуальная категория «Другое».
3. **Фото блюда (`photo_url`)?** Рекомендация: не в этом спринте (нужен `sendPhoto` и хранение файлов); поле игнорируем.
4. **Нужен ли поиск по алиасам («тзатзики» / «дзадзики»)?** Рекомендация: нет, только подстрока в названии; алиасы — в бэклог до S09.

## 5. Что показываем на приёмке

Данные — seed ресторана Лавраки.

1. `/start` → «❓ Частые вопросы» → 6 вопросов → «Можно ли с животными?» → «Только на веранде.» → «← К вопросам» возвращает список.
2. «🍽 Меню» → 4 категории (Мезе, Рыба и морепродукты, Десерты, Вино) → «Рыба и морепродукты» → в списке нет «Рыбы дня» (не опубликована), «Креветки саганаки» с пометкой «недоступно».
3. «Дорада на гриле» → карточка: цена `24,00 €`, КБЖУ с `У 0`, предупреждение про аллергию.
4. «Тарамасалата» → «Состав: нет данных…», «КБЖУ на порцию: нет данных…».
5. Написать «саганаки» → кнопки «Мидии саганаки» и «Креветки саганаки (недоступно)».
6. Написать «осьминог» → сразу карточка. Написать «пицца» → «Не нашёл такого блюда» + кнопки меню. Написать «%» и «а» → не всё меню и не ошибка, а просьба уточнить запрос.
7. «Рыба дня» по названию текстом → «Не нашёл» (скрытое блюдо не светится в поиске).
8. «📅 Забронировать стол» и «💬 Связаться с менеджером» по-прежнему отвечают заглушкой.
9. В БД: все реплики (`[кнопка] dish:…`, карточки) лежат в `messages`; повторный update не дублирует.
10. `deno test` — зелёный (форматтеры, `normalizeSearchQuery`, `parseCallback`); `deno check`, `pnpm check:layers` — чисто.
