# Документация Гостевой бот ресторана

Документация реализации. Проектные решения — здесь; входные материалы (продуктовый документ, стек,
дизайн) кладутся в `product/` и не редактируются.

## Порядок чтения

Новому человеку в проекте — строго в этом порядке:

1. [`STATE.md`](STATE.md) — **где мы стоим прямо сейчас**: что построено, что осталось, чем код
   отличается от ADR. Короткий, читается первым.
2. `product/` — что за продукт и где его границы (если материалы есть).
3. [`architecture/decisions.md`](architecture/decisions.md) — как решили строить и почему.
   **Это закон.** Решения со статусом «Отложено» — зафиксированные упрощения, их отсутствие в коде не баг.
4. [`architecture/domain-model.md`](architecture/domain-model.md) — сущности, поля, инварианты.
5. [`roadmap/README.md`](roadmap/README.md) — **действующий план**: спринты, что упрощено и почему, DoD.
6. [`roadmap/sprints/`](roadmap/sprints/) — спринты по одному вертикальному срезу (схема + сервер + экран).
7. [`bugs/README.md`](bugs/README.md) — открытые и закрытые находки.
8. [`archive/README.md`](archive/README.md) — архив (журнал завершённых спринтов, QA, отработавшие архитектурные документы): за причиной конкретного решения,
   не для обзора.

## Карта документов

```
docs/
├─ README.md                     этот файл
├─ STATE.md                      где стоим: построено, отложено, хвосты (обновляется в конце спринта)
├─ architecture/
│  ├─ decisions.md               ADR-001… — принятые решения, «закон»
│  └─ domain-model.md            доменная модель, сущности, инварианты
├─ product/                      входные материалы (не редактируются)
├─ bugs/                         баг-репорты: находки вне рамок текущей сессии
│  ├─ README.md                  правила, таблица открытых и закрытых
│  ├─ TEMPLATE.md                шаблон репорта
│  └─ frontend/ backend/ tooling/   BUG-NNN-*.md, нумерация сквозная
├─ archive/                      архив закрытого (в контекст сессий не тянется)
│  ├─ README.md                  указатель + ритуал закрытия спринта
│  ├─ log/<спринт>.md            записи из LOG.md, дословно (плоско)
│  ├─ qa/<спринт>.md             записи из QA.md, дословно (плоско)
│  └─ architecture/              отработавшее: решённые гипотезы, выполненные планы
└─ roadmap/                      действующий план
   ├─ README.md                  спринты, что упрощено и почему
   └─ sprints/<спринт>-*.md      спринты, один срез = схема+сервер+экран
```

## Разделение LOG / STATE

`LOG` отвечает на «почему решили так» и растёт бесконечно — архив в `archive/log/`.
`STATE` отвечает на «что уже есть» и остаётся коротким — тянется в контекст каждой сессии.
