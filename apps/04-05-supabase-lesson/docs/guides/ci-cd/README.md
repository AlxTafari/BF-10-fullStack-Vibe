## Словарь

Термины в том виде, в каком они встречаются в интерфейсе GitHub и в документации.

- **CI (Continuous Integration, непрерывная интеграция).** Каждое изменение автоматически собирается и
  проверяется: типы, линтер, тесты. Цель — узнать о поломке через минуты после push, а не через неделю.
- **CD.** Две расшифровки, их часто путают:
  - **Continuous Delivery (непрерывная поставка)** — каждое зелёное изменение *готово* к выкладке, но
    выкладывает человек (кнопкой).
  - **Continuous Deployment (непрерывное развёртывание)** — каждое зелёное изменение в `main` выкладывается
    *само*. У нас выбрано это (S08, вопрос 2), а кнопку подтверждения можно включить позже.
- **Pipeline (конвейер).** Вся цепочка от push до prod: проверки → тесты → деплой. В GitHub Actions конвейер
  описывается одним или несколькими workflow.
- **Workflow.** YAML-файл в `.github/workflows/`. Описывает, *когда* запускаться (`on`) и *что* делать (`jobs`).
  У нас: `guest-bot.yml` (гостевой бот) и `ci.yml` (конвертер валют).
- **Run (прогон).** Один запуск workflow. Виден во вкладке Actions репозитория.
- **Job.** Крупный этап внутри workflow. Каждый job получает **свою чистую виртуалку** и по умолчанию идёт
  параллельно с другими. Порядок задаётся через `needs`.
- **Step (шаг).** Одна команда (`run`) или одно готовое действие (`uses`) внутри job'а. Шаги одного job'а идут
  по очереди на одной машине и видят файлы друг друга.
- **Runner (раннер).** Машина, на которой выполняется job. `ubuntu-latest` — виртуалка, которую GitHub даёт на
  время job'а и потом уничтожает. Для публичного репозитория минуты бесплатны.
- **Action.** Переиспользуемый шаг, опубликованный кем-то (`actions/checkout`, `pnpm/action-setup`).
  Подключается через `uses: владелец/репозиторий@версия`.
- **Trigger (событие).** Что запускает workflow: `push`, `pull_request`, `workflow_dispatch` (кнопка), `schedule`
  (по расписанию) и другие.
- **Artifact (артефакт).** Файл, который job сохраняет после себя (сборка, отчёт), чтобы его скачать или
  передать другому job'у. Виртуалка исчезает — артефакт остаётся.
- **Status check (статус проверки).** Галочка или крестик у коммита и на странице PR — результат job'а.
- **Branch protection (защита ветки).** Правило репозитория: например, «в `main` нельзя push напрямую» или
  «merge только при зелёных проверках». У нас выключена намеренно — заметка 02, последний раздел.
