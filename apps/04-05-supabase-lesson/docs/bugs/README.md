# Баг-репорты

Накопитель находок, которые всплыли **не в свою сессию**: прогон одного спринта находит баг
другого, ревью находит проблему, которую в ревью не чинят, диагностика цепляет проблему окружения.
Чинить их на месте — расползание сессии; забыть — потерять. Поэтому сюда.

## Правила

- **Заводим репорт, а не чиним, если находка вне рамок текущей сессии** — другой спринт, другой
  слой, или сессия по своей роли не правит код (ревью, прогон, диагностика).
- **Находка в рамках сессии чинится в сессии**, репорт не нужен.
- Один файл — один баг. Имя: `BUG-NNN-kratkij-slug.md`, нумерация **сквозная по всем папкам**.
- Шаблон — [`TEMPLATE.md`](TEMPLATE.md). Обязательны: симптом, шаги, ожидание/факт, где смотреть.
- **Причину помечаем честно:** «подтверждена» (лог, стектрейс, DOM, запрос к БД) или «гипотеза».
  Гипотеза, поданная как факт, стоит потом лишнего часа.
- Закрывая баг — статус `fixed`, дата и коммит в шапке файла; файл не удаляем, строку в таблице
  не стираем — переносим в «Закрытые».

## Папки

| Папка | Что кладём |
|---|---|
| `frontend/` | экраны, компоненты, контракты со стороны клиента, стили, навигация |
| `backend/` | сервисы, репозитории, обработчики запросов, схема БД, миграции |
| `tooling/` | окружение, dev-workflow, сборка, линтеры, генерация клиента |
