# BUG-003 — «Этот вариант уже недоступен» на шаге «сколько гостей» без видимой причины

- **Статус:** open
- **Важность:** low
- **Область:** backend
- **Модуль:** бот, сценарий брони (`bookingFlow`), шаг `guests`
- **Найден:** 2026-11-10, S08 сессия 3, ручная проверка prod после первого CI-деплоя (шаг Е4 чек-листа)
- **Спринт-источник:** не относится к S08 (сценарий брони — S03, чистый чат — S06d)
- **Исправлен:** —

## Симптом

Во время брони бот ответил:

> Этот вариант уже недоступен. Выберите другой.
>
> Сколько будет гостей? Напишите число от 1 до 20.

Гость при этом ничего «недоступного» не выбирал, на экране уже был вопрос о числе гостей. Текст читается
как «выбранное время занято», хотя занятости в боте нет (см. «Причина»).

## Воспроизведение

Точная последовательность нажатий не записана. Предполагаемая (гипотеза, не проверена):

1. `/start` → бронь → дата → период.
2. Быстро нажать кнопку часа два раза (или нажать кнопку часа на старом сообщении, когда бот уже спросил
   о числе гостей).

**Ожидается:** второе нажатие игнорируется молча (или ответ «этот шаг уже пройден»), бот ждёт число гостей.
**Фактически:** «Этот вариант уже недоступен. Выберите другой.» + повтор вопроса о гостях.

## Причина

**Гипотеза** (по коду, на живом прогоне не подтверждена).

Сообщение — код ошибки `unavailable` (`content.ts:131`). На шаге `guests` он возвращается на **любое**
нажатие кнопки, кроме `keep` и `to_manager` (`bookingFlow.ts:189`). Повтор того же апдейта отсеивается по
`update_id` (`router.ts:47`), а второе нажатие — это новый апдейт с новым `update_id`, поэтому до сценария
доходит: первое нажатие `h=19` переводит на шаг `guests`, второе `h=19` приходит уже на шаге `guests` и
получает `unavailable`.

Версия «бот предлагает занятое время» **исключена**: доступные даты и часы (`bookingRules.ts`,
`availableDates` / `availableHours`) считаются только по часам работы, минимальному запасу до брони и
горизонту дней. Существующие брони не учитываются вовсе — понятия занятости в MVP нет.

## Где смотреть

- `supabase/functions/_shared/domain/bookingFlow.ts:189` — на шаге `guests` чужая кнопка → `unavailable`
- `supabase/functions/_shared/domain/bookingFlow.ts:166`, `:172`, `:178` — так же на шагах `date`, `period`, `hour`
- `supabase/functions/_shared/content.ts:131` — текст ошибки, звучит как «слот занят»
- `supabase/functions/telegram-webhook/router.ts:47` — дедупликация только по `update_id`

## Заметки

- Подтвердить: в логах функции `telegram-webhook` (Dashboard → Edge Functions → Logs) найти два
  `callback_query` подряд с одинаковыми данными кнопки часа.
- Варианты починки: кнопка предыдущего шага на текущем шаге — молча ответить на `callback_query` без
  сообщения; либо отдельный код ошибки «этот шаг уже пройден» вместо `unavailable`; либо снимать клавиатуру
  с сообщения сразу после нажатия (связано с S06d «чистый чат», BUG-001, BUG-002).
- Учёт занятости столов — не баг, а отсутствующая функция MVP; если понадобится, это продуктовое решение
  для роадмапа, не починка.
